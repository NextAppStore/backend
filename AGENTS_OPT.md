# Backend Sub-Harness (Level 2) — Rules & Operational Invariants

> **Hierarchy:** Inherits all global system invariants, host isolation mandates, and zero-trust policies from Level 1 (`../AGENTS.md` / `../org-docs/AGENTS.md`).
> **Scope:** Strictly scoped to `backend/` (FastAPI REST service, SQLAlchemy models, Alembic migrations, Celery dispatch, and OpenStack/Keycloak integration).

---

## 1. Domain Invariants & Architecture Guardrails

### A. API Contract Synchronization (SSOT)

- `backend/openapi.json` is the sole Single Source of Truth for the frontend API client and TypeScript definitions.
- **Mandatory Export Rule:** Modifying endpoints (`app/routers/`), schemas (`app/schemas.py`), or query/path parameters requires re-exporting the OpenAPI spec before concluding a task:
  ```bash
  python3 ../agentic-harness/sandbox.py "python3 backend/export_openapi.py"
  ```
- **Invariant:** A task touching API routes or models is strictly **INCOMPLETE** if `openapi.json` is out of sync.

### B. Database Schema & Alembic Migrations

- **Zero Schema Drift:** Modifying SQLAlchemy entities in `app/models.py` requires an autogenerated, reviewed Alembic migration in `backend/alembic/versions/`.
- **Soft Deletes:** `App` and `Deployment` use `deleted_at`. All default read/list queries MUST filter `Model.deleted_at.is_(None)`. Hard deletes are forbidden unless explicitly pruning unreferenced tombstones.
- **Migration Verification:** Test migrations against sandbox PostgreSQL:
  ```bash
  python3 ../agentic-harness/sandbox.py "service postgresql start >/dev/null 2>&1 && \
    su - postgres -c \"psql -c \\\"CREATE USER testuser WITH PASSWORD 'testpass' SUPERUSER;\\\"\" >/dev/null 2>&1 || true; \
    su - postgres -c \"createdb -O testuser testdb\" >/dev/null 2>&1 || true; \
    export DATABASE_URL=\"postgresql+psycopg2://testuser:testpass@localhost:5432/testdb\" && \
    export CREDENTIAL_ENCRYPTION_KEY=\"MDEyMzQ1Njc4OTAxMjM0NTY3ODkwMTIzNDU2Nzg5MDE=\" && \
    export SECRET_KEY=\"test-secret-key-for-harness-testing-only\" && \
    cd backend && alembic revision --autogenerate -m '<migration_title>' && alembic upgrade head"
  ```
- **Review Rule:** Verify autogenerated migration files for reversible `downgrade()`, cascading foreign keys, and absence of accidental table/column drops.

### C. Non-Blocking FastAPI & Two-Phase Task Dispatch

- **Zero Blocking I/O in Handlers:** Never execute OpenStack provisioning, Terraform calls, or Packer builds synchronously in FastAPI HTTP threads.
- **Two-Phase Dispatch Protocol (`app/services/task_service.py`):**
  1. _Phase 1 (In-Transaction):_ Insert `Task(status=TaskStatus.PENDING)` via `prepare_task_in_tx(db, ...)`.
  2. _Phase 2 (Commit):_ Commit the surrounding database transaction (`db.commit()`) to guarantee persistence before Celery consumes the task.
  3. _Phase 3 (Out-of-Transaction Dispatch):_ Call `dispatch_to_celery(db, task, ...)` to submit to RabbitMQ and record `celeryTaskId`.
  4. _Phase 4 (Response):_ Return `HTTP 202 Accepted` with task ID and status polling endpoint.

### D. Security, Multi-Tenancy & Secrets

- **JWKS Signature Verification:** Always validate token signatures against Keycloak/Moodle JWKS (`verify_signature: True`, `verify_exp: True`). Never disable signature checks in `app/`.
- **Strict Course Multi-Tenancy:** Filter every deployment, VM, and task query by course context (`context.id` / `courseId`). Enforce `#Instructor` permissions for mutation endpoints and `#Learner` read-only self-endpoints.
- **At-Rest Secret Encryption:** All user OpenStack credentials and application secrets must be encrypted using `app.utils.crypto.encrypt` / `encrypt_b64` with `CREDENTIAL_ENCRYPTION_KEY`. Plaintext secrets must never appear in database columns, logs, or API response schemas.

## 3. Explicit Anti-Patterns (Negative Guardrails)

- ❌ **DO NOT** execute `pytest`, `ruff`, `alembic`, or `poetry` directly on the host machine.
- ❌ **DO NOT** perform direct OpenStack or Terraform calls within FastAPI route functions.
- ❌ **DO NOT** trigger `celery_app.send_task` or `dispatch_to_celery` prior to committing the DB transaction.
- ❌ **DO NOT** bypass JWT verification (`verify_signature=False`) in application code.
- ❌ **DO NOT** return unredacted credentials or sensitive tokens in Pydantic response models.
- ❌ **DO NOT** query `App` or `Deployment` without handling soft-deletes (`deleted_at.is_(None)`).
- ❌ **DO NOT** modify `app/models.py` without generating and verifying an Alembic revision.
- ❌ **DO NOT** modify API routers or response schemas without synchronizing `backend/openapi.json`.
